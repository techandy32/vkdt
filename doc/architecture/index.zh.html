RAW 文件如何变成一张照片

vkdt 在显卡上冲洗 RAW 照片和视频。每一个图像操作都是一个小的 GPU 程序，整个应用围绕一个结构来组织：由这些程序组成的图。本指南先跟随一张图像走过这张图，再逐一查看让它运转起来的各部分代码。

跟随一张图像走过整张图

在暗房（darkroom）中打开一个 RAW 文件时，vkdt 会加载下面这张图。列表中的每一行是一个模块：一个图像操作，带有输入、输出和参数。按播放，或选中某个模块，就能看到它交给下一个模块的缓冲区。

CPU 只在两端干活
i-raw 在 CPU 上解码文件，并且只上传一次。此后图像一直留在 GPU 内存里，直到抵达汇（sink），也就是图的终点。

上面的列表保存在照片旁边，文件名是 IMG_0412.CR2.cfg。除此之外没有别的东西描述这次编辑，原始文件也从不会被改动。
是图，不是链

src/pipe/module.h · src/pipe/modules/colour/ · src/gui/shd/gui.frag 目录 ↑

数值在哪里改变含义

同一个像素在图的不同位置存着完全不同的数值。它们的含义写在两个标签里，标签随每个缓冲区一起传递：三个通道参照的是哪组基色，以及数值是用哪条传递曲线编码的。下面跟随六个色块，从传感器一路走到屏幕。

元数据随图像一起传递
当尺寸沿着图向前传递时，每个模块都会收到其输入的图像元数据的一份副本：黑电平和白电平、白平衡、滤色片排列、相机矩阵、噪声特性文件、曝光数据，以及两个色彩标签。如果模块改变了数据的含义，它就修改这份副本：demosaic 清除滤色片排列，colour 把标签设为 rec2020 和线性。
只有一个工作空间
从 colour 开始，一切都是线性 rec2020。模块不必去问自己拿到的是什么数据，界面也在同一个空间里绘制自己的控件。
其他输入自己声明身份
jpg 进来时带着 sRGB 基色和 sRGB 曲线的标签。exr 通常标记为 rec2020、线性。colour 读取这些标签并去掉曲线编码，所以图的其余部分根本察觉不到区别。
通过文件离开
导出时，display 汇会被替换成一个输出模块。如果文件是 8 位，或者你要的不是线性 rec2020，就会在它前面放一个 colenc。colenc 转换到你指定的基色和曲线；导出面板默认是 sRGB。
显示器排在最后
每台显示器对应一个小文本文件，里面有一个 gamma 值和一个 3 × 3 矩阵。界面的片段着色器把它们应用到整个窗口，然后抖动到 8 位或 10 位。没有这个文件时，着色器假定显示器是 sRGB。
缩略图走了条捷径
缩略图以 rec2020 基色和 sRGB 曲线存储。纹理格式会让 GPU 在采样时去掉曲线编码，所以在界面内部它们又是线性的。

src/pipe/module.h · src/pipe/node.h 目录 ↑

你编辑的是模块，GPU 运行的是节点

图有两份。模块图是 .cfg 文件所描述的，也是你在界面里看到的。节点图才是实际执行的：每个节点是一次着色器运行，通常是单次计算分派（dispatch）。

每个模块通过自己的 create_nodes 回调把自己变成节点。没有这个回调的模块会变成单个节点，运行它的 main.comp 着色器；grade 和 exposure 就是这样。而像 llap 这样的模块会构建一整座金字塔。

节点的数量可能取决于图像尺寸，所以要等尺寸确定之后才创建节点。一张图最多可以容纳 100 个模块和 2000 个节点。

模块和节点通过连接器交流。连接器有名称、类型、通道布局和像素格式，例如 output:write:rgba:f16。* 表示空位，由连线的另一端填入，所以像 exposure 这样的模块可以处理任何缓冲区。

colour、rgba、f16 这样的名字是令牌（token）：最多八个字符打包进一个 64 位整数，所以比较两个名字只需一次整数比较。这就是为什么 vkdt 里没有任何模块、连接器或参数的名字超过八个字符。

src/pipe/graph.c · dt_graph_run() 目录 ↑

图运行一次做了什么

一切都经过同一个函数 dt_graph_run。它接收一组标志，说明需要哪些阶段，所以小改动可以跳过开销大的准备工作。选一下刚才发生了什么，看看哪些阶段会运行。

注意拖动滑块时没有发生什么：什么都不重建，也不按模块缓存任何东西。参数被重新写入，整张图在 GPU 上再跑一遍。vkdt 靠的是完整运行足够快，不缓存中间结果。

src/pipe/graph-run-nodes-record-cmd.h 目录 ↑

GPU 实际收到的指令

录制阶段遍历排好序的节点列表，写出一个 Vulkan 命令缓冲区。每个计算节点都加入同样的一小段命令。这份列表就是 GPU 在一次运行中收到的全部内容；在源和汇之间，CPU 不做任何逐像素的工作。

一次分派（dispatch）以 8 × 8 像素为一组覆盖节点的输出，所以 6000 × 4000 的节点是 750 × 500 组：每个像素调用一次着色器。图像在整个生命周期里都保持同一种布局（GENERAL），这让节点之间的屏障（barrier）很简单。

每个着色器都在相同的位置找到它的输入：

位置内容在着色器中
set 0, binding 0对每个节点都相同：帧号、帧数、主图像的哈希值、两种界面颜色uniform global_t
set 0, binding 1这个节点所属模块的参数uniform params_t
set 0, binding 2存储缓冲区的地址，只有少数节点用到uniform bref_t
set 1, binding N这个节点的第 N 个连接器，按声明的顺序编号输入用 sampler2D，输出用 image2D
set 2光线追踪场景，只在用到它的图里才有accelerationStructureEXT

用 -d perf 启动 vkdt 或 vkdt-cli，每次运行后都会打印各个节点在 GPU 上花的时间。图中看到的时间戳（timestamp）就是用来测这个的。

draw 和 overlay 这两个模块走的是光栅化：别的节点录制一次分派的地方，它们的节点录制一次绘制调用（draw call）。

src/pipe/alloc.c · src/pipe/graph-run-nodes-allocate.h 目录 ↑

几块内存，事先规划好

一张 2400 万像素的图像，存成四个 16 位浮点通道，约占 190 MB。有几十个节点的图不可能给每个输出都单独分一块缓冲区。所以 vkdt 先做规划：按执行顺序遍历节点，把每个输出放进第一个放得下的空隙；最后一个读取它的节点一运行完，就释放这块缓冲区。

这次遍历只计算偏移。遍历结束后，vkdt 对每个内存块调用一次 vkAllocateMemory，再把每张图像绑定到各自的偏移上。内存块有四种：可回收的图像、受保护的图像、CPU 可见的暂存缓冲区，以及 uniform。逐帧运行期间不再申请设备内存。

有些缓冲区受保护，不会被回收：源、汇，以及后面的帧还要再读的任何数据。

src/pipe/anim.h · src/pipe/connector.h 目录 ↑

帧、关键帧与反馈

一张图有帧数和帧率，在 .cfg 里存为 frames: 和 fps: 两行。对于视频、延时摄影和带动画的参数，界面推进帧号，再运行一次图。只有命令缓冲区重新录制；节点和内存保持原样。

关键帧记录某个帧号上的参数值。每次帧号变化，vkdt 都在相邻的两个关键帧之间对浮点参数插值：线性、缓入或缓出、平滑，或者阶跃。其他类型的参数在关键帧处直接切换，只有 draw 的笔触例外，它们也会被插值。

反馈连接器把模块上一帧的输出带到当前帧。帧累积、时域降噪和模拟都是这样实现的。反馈缓冲区有两份。每一帧写其中一份、读另一份，然后两者交换。

src/fit/fit.c · src/pipe/modules/loss/ 目录 ↑

把图当作函数：vkdt-fit

图把参数变成像素，而且不需要窗口就能运行成千上万次。vkdt-fit 利用这一点来搜索参数值。你指定要调整的参数，再指定一个目标（target）：它也是一个参数，由某个模块填入对结果的测量值。

有两个模块产生这样的测量值。loss 把输入与参考图像比较，保存均方差。pick 对选定位置的颜色取平均并保存；在差值模式下，它还保存这些颜色与参考颜色相差多远。两者都在 GPU 上把图像缩减成少量数据，再通过 write_sink 收到几个数。

每次求值时，候选值直接写进参数内存，图带着三个标志运行：录制、下载、等待。什么都不重建，所以一次求值的开销只比 GPU 计算本身多一点。搜索不会超出每个参数滑块的范围；结束时，整张图连同拟合出的值以 .cfg 的形式打印出来。

仓库里的一个实际用例：胶片模拟模块的中性滤镜设置表。一块灰色色块经过 filmsim 进入 pick，调整三个参数，直到取到的颜色与这块灰一致。

vkdt-fit -d none -g neutral-start.cfg \
  --param "filmsim:01:filter m" \
  --param "filmsim:01:filter y" \
  --param "filmsim:01:ev paper" \
  --target "pick:01:de76" \
  --nelder-mead \
  --config "param:filmsim:01:film:$f" "param:filmsim:01:paper:$p"

默认的搜索方法是 Gauss-Newton。也可以改选 Adam 或 Nelder-Mead。上面的例子用的是 Nelder-Mead。

src/pipe/modules/exposure/ 目录 ↑

模块的内部

一个模块就是一个文件夹。最简单的模块完全不含 C 代码。exposure 只有三个很小的文本文件和一个着色器。拖动图中的滑块，看一个数值怎样从界面一路传进着色器。

如果模块需要不止一个着色器，或者要读写文件，就加一个 main.c，由它导出回调函数。每个回调都是可选的，大约五分之一的模块一个也不导出。

回调调用时机典型用途
modify_roi_out尺寸向前传递时声明输出尺寸和图像元数据；输入模块在这里读取文件头
modify_roi_in尺寸向后传递时请求更大、更小或完整尺寸的输入
create_nodes尺寸确定之后构建模块自己的节点图：金字塔、迭代、多个着色器
commit_params每次运行之前把界面上的数值转换成着色器需要的形式，例如把色温转换成矩阵
check_params某个参数改变时说明重新运行一次就够，还是必须重建图
read_source上传源（source）时在 CPU 上解码文件，写入暂存缓冲区
write_sink下载汇（sink）时编码像素，写出 jpg、exr 或视频帧
animate每次运行开始时推进模拟，或要求在这次运行中上传或下载
input · ui_callback模块接管鼠标和键盘时，或它的按钮被按下时rt 和 quake 里的相机控制；各种按钮，例如 crop 的自动裁剪
audio音频后端需要采样数据时视频输入模块交出自己的音轨
init · cleanup实例被创建或移除时分配和释放每个实例的状态

构建时，每个着色器被编译成 SPIR-V（main.comp.spv），每个 main.c 被编译成 lib<name>.so。启动时 vkdt 扫描模块目录，读取这些文本文件并加载这些库。新模块就是一个新文件夹，不需要登记到任何总列表里。

src/pipe/modules/<yours>/ 目录 ↑

编写你自己的模块

模块只是一个文件夹，所以添加一个模块只需要五个小文件，其他地方都不用改。这里的例子是一个虚构的模块 desat，它把画面褪成灰色。它逐行仿照 exposure 写成，但没有在 vkdt 里编译或运行过，所以请把它当作草稿。

一个着色器不够用时，添加一个带 create_nodes 回调的 main.c，并在旁边放一个 flat.mk（可以是空文件，但构建规则需要它存在）。下面是色度图模块 ciediag 里 create_nodes 的全部内容。一个节点把像素统计成直方图，另一个节点把计数变成图片。

const int id_collect = dt_node_add(graph, module, "ciediag", "collect",
  module->connector[0].roi.wd, module->connector[0].roi.ht, 1, 0, 0, 2,
  "input",  "read",  "rgba", "f16",  dt_no_roi,
  "output", "write", "r",    "ui32", &module->connector[1].roi);
graph->node[id_collect].connector[1].flags = s_conn_clear;
const int id_map = dt_node_add(graph, module, "ciediag", "map",
  module->connector[1].roi.wd, module->connector[1].roi.ht, 1, 0, 0, 2,
  "input",  "read",  "r",    "ui32", dt_no_roi,
  "output", "write", "rgba", "f16",  &module->connector[1].roi);
dt_connector_copy(graph, module, 0, id_collect, 0);
dt_node_connect  (graph, id_collect, 1, id_map, 0);
dt_connector_copy(graph, module, 1, id_map, 1);
dt_node_add
依次是：文件夹名和着色器名，分派（dispatch）的宽、高、深，push constant（这里没有），连接器的数量，以及每个连接器的五个值。输出要给出尺寸；输入写 dt_no_roi，尺寸取自它所连的那一端。
dt_connector_copy
把模块的一个连接器绑定到节点的一个连接器上。这里模块的 input 其实就是第一个节点的输入，它的 output 就是第二个节点的输出。
dt_node_connect
模块内部两个节点之间的连线。模块外面永远看不到它。

常见错误

参数顺序很重要
参数按文件中的顺序打包，并逐字节复制到 uniform 块里。params 里的顺序必须与 params_t 的字段一致，而且打包结果本身就要符合 GLSL 的 std140 规则：把 vec4 声明为 float:4，不要用 vec3。
include 需要构建规则
构建时不会扫描着色器里的 #include。如果你的着色器引入了别的文件，就在 flat.mk 里加一行依赖，这样那个文件改动时着色器会被重新构建。
先检查连线
vkdt-cli --dump-modules 和 --dump-nodes 以 graphviz 格式打印图，分别对应模块展开成节点之前和之后。

src/pipe/modules/{filmcurv,llap,denoise,grade}/ 目录 ↑

四个模块，四个公式

这套架构存在的目的，就是运行一小段一小段的图像数学。这里是其中四段，取自默认图里的着色器。移动滑块，曲线会按着色器所用的同一个公式重新计算。

hilite
为半尺寸的 RAW 图像构建金字塔。每个更粗的层级只对没有过曝截断的相邻像素求平均。往回向上重建时，过曝截断的像素取粗层级的颜色，并缩放到与较细层级中仍然可信的通道一致。一张 2400 万像素的 RAW 文件大约需要 22 个节点。
demosaic
三种方法。默认方法对每个块里的绿色像素拟合一个小的有方向的高斯，沿这个方向插值出绿色，再按与绿色的比值填充红色和蓝色。RCD 是用于 Bayer 传感器的另一种方法。半尺寸方法把每个块合并成一个像素。
crop
一个节点。对每个输出像素，它先旋转，再应用由四个角点解出的透视变换，然后在得到的位置对输入采样。
hist
两个节点。第一个做散射（scatter）：每个输入像素给一张 1000 × 600 图像里的某个计数器加一，三个通道各占十位，打包进一个 32 位整数。第二个把计数变成亮度。

src/gui/main.c 目录 ↑

围绕图的应用程序

GUI 是主线程上的一个普通循环。参数改变后，它不会等图像算完：图被提交到 GPU 的计算队列，循环继续绘制界面。之后的某一轮循环会取到算好的图片。只有在需要上传源（source）、下载汇（sink）或重建图时，循环才会阻塞。

四个视图，一张图
files 用来浏览和导入，lighttable 显示缩略图，darkroom 编辑一张图像，nodes 把同一张图显示成方框和连线。暗房和节点编辑器共用一个图对象，所以可以随意切换。
控件来自文本
暗房读取每个模块的 params.ui，画出对应的控件：滑块、下拉框、色轮、裁剪和透视工具，一共大约二十五种控件。
色彩管理放在最后
用于显示的汇（sink）接收线性 rec2020。界面自己的片段着色器在最后一步才转换到显示器的色彩特性文件，图像和控件都一样处理。
缩略图也是图
线程池中有两个工作线程，各自拥有一张图和一个工作队列。它们运行图像的 .cfg，把结果送进 o-bc1 模块，保存成一个采用 GPU 压缩格式、再经 gzip 压缩的文件。看片台不用转换像素就能直接上传它。
一张图，一个线程
一张图在任何时刻只由一个线程运行。一个线程池为每个 CPU 核心配一个工作线程，负责缩略图、导出、文件复制和音频播放。
默认全分辨率
无论是否放大，暗房都处理图像的每一个像素。有一个细节级别设置可以降低处理的分辨率。另一个设置只在拖动滑块期间生效。
无界面（headless）用的是同一套代码
vkdt-cli -g photo.cfg --format o-jpg 在没有窗口的情况下初始化 Vulkan，加载同一张图，并把用于显示的汇（sink）换成文件输出。

src/pipe/graph-history.h 目录 ↑

撤销就是重放

暗房会记录你的编辑历史，历史的内容和其他一切一样，都是文本行。vkdt 不保存“怎样把某次编辑反过来做”的信息。要回退时，它重置图，再把这些行重放到你选的位置。

历史只保存在内存里。历史面板（ctrl-h）还可以把列表压缩成对当前图的一份简明描述，回滚到磁盘上的文件，或者重置为默认图。

src/core/threads.c · src/qvk/qvk.h 目录 ↑

线程与 GPU 队列：谁运行什么

vkdt 启动一个工作线程池，每个 CPU 核心一个线程，并向 GPU 申请最多五个队列。每个图同一时刻只由一个线程运行，通常只向一个队列提交。每个队列有一把锁，所以两个线程不会同时向同一个队列提交。

src/db/thumbnails.c 目录 ↑

看片台的图片从哪里来

缩略图就是图像自己的图，以小尺寸运行一遍。不为它另存任何特殊数据，它也不会在不知不觉中过期：如果 .cfg 比缓存的缩略图新，缩略图就会重新渲染。

每像素半个字节
缩略图以 BC1 存储，这是一种显卡可以直接采样的块格式。磁盘上的文件还经过 gzip 压缩；解压后，这些块不经转换直接上传，默认的 16 MB GPU 内存里放得下几百张缩略图。
最近最少使用
缓存的槽位数量固定，每 MB 21 个。全部占满后，加载器最久没有碰过的那个槽位会被重新使用。如果内存先于槽位用完，整个缓存会被丢弃，并以两倍大小重建。
离开暗房时开销更小
图片已经在 GPU 上，所以 vkdt 用一个小着色器把显示图像缩小，再用它写出缩略图。图不会再运行一次。
失败看得见
如果某张缩略图无法渲染，它的缓存文件会变成一个链接，指向一张预置的炸弹图片，这样在看片台上就能看出有地方出了问题。

src/db/ 目录 ↑

你的文件夹就是数据库

没有图库文件，也没有导入步骤。vkdt 打开一个目录，直接使用里面已有的东西。原始文件从不被写入，也从不被移动。

~/Pictures/harbour/              你让 vkdt 打开的任意文件夹
├─ IMG_0412.CR2                  你的原始文件，从不修改
├─ IMG_0412.CR2.cfg              附属文件（sidecar）：这张图像的完整处理图
├─ IMG_0412.CR2_01.cfg           副本：对同一文件的第二份编辑
└─ vkdt.db                       此文件夹的评分、色标、排序方式和筛选条件

~/.config/vkdt/
├─ config.rc                     设置
├─ presets/*.pst                 你的预设
└─ tags/sunset/<hash>.cfg        指向附属文件的符号链接：标签也是一个文件夹

~/.cache/vkdt/
└─ <hash>.bc1                    缩略图，以 GPU 压缩格式存储

没有附属文件的图像会得到一个默认图。vkdt 根据文件扩展名选择输入模块，并从 bin/default-darkroom.i-raw 开始；jpg、视频和其他输入则用各自对应的文件。

评分和色标属于文件夹，而不属于图像。一个标签（tag）就是一个装着符号链接的目录，带有自己的 vkdt.db，所以你可以像打开任何文件夹一样打开它，并在那里给同样的图片打不同的评分。

预设（.pst）使用与 .cfg 相同的行格式，但它只是一个片段：它的各行应用在当前图之上，用来添加模块、重新连线和设置参数。

Makefile · src/Makefile · bin/config.mk.defaults 目录 ↑

从源码树到运行的程序

构建用的就是普通的 make。没有 configure 步骤，也不生成工程文件：模块靠通配符找到，一个很小的开关文件决定编译进哪些功能。

开关增加的功能默认
VKDT_USE_RAWINPUTi-raw 背后的 RAW 加载器：2 是用 Rust 写的 rawler；1 是用 C++ 写的 rawspeed；0 表示不用找到 Rust 编译器时为 2
VKDT_USE_FFMPEG视频输入和输出，i-vid 和 o-vidffmpeg 命令报告的版本为 6 或更新时开启
VKDT_USE_PIPEWIRE音频播放找到该库时开启
VKDT_USE_JXLjpeg-xl 输出，o-jxl找到该库时开启
VKDT_USE_MLV · VKDT_USE_MCRAWMagic Lantern 和 MotionCam 的 RAW 视频输入开启
VKDT_USE_V4L2网络摄像头输入，i-v4l2开启
VKDT_USE_QUAKE光线追踪的游戏模块关闭
常用的 make 目标
make debug 不带优化构建，并打开 Vulkan 验证层。make sanitize 加上 address sanitizer。make install 把可执行文件、模块和数据复制到安装前缀下的 lib/vkdt/。
工具链
几乎所有代码都是 C，默认编译器是 clang。C++ 只用于 exr 和 MotionCam 模块以及可选的 rawspeed 加载器，Rust 用于 RAW 加载，glslangValidator 用于着色器。必需的库有 Vulkan、glfw、libjpeg 和 zlib。
文件在哪里查找
默认文件、预设和数据先在图所在的文件夹里查找，然后是 ~/.config/vkdt，最后是可执行文件旁边。在你的配置文件夹里放一个同名文件，就会覆盖随程序附带的那个。

代码里用的词

module
用户眼中的一个图像操作：一个名字、一个实例、若干连接器和参数。
节点（node）
一次着色器运行。模块创建节点；GPU 看到的永远只有节点。
连接器（connector）
模块或节点的一个输入或输出，带有通道数和像素格式。
源（source）· 汇（sink）
数据进入或离开图的连接器：文件经由 CPU，显示则通过一次 GPU 拷贝。
roi
感兴趣区域（region of interest）。一个缓冲区可以有的尺寸（full_wd、full_ht）和实际计算的尺寸（wd、ht）。
令牌（token）
一个最多八个字符的名字，存放在一个 64 位整数里。
反馈（feedback）
把上一帧的输出送到当前帧的连线。
dspy
模块可选的诊断输出，比如一张曲线图。选中该模块时，暗房会把它连到一个临时的 display:dspy 汇上。
